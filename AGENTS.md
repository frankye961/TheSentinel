# Repository instructions

- The project owner writes production logic. Codex scaffolds, reviews, assesses progress, and maintains documentation. Write production logic or tests only when the owner explicitly requests them. The skeleton-only boundary applies to the initial assignment; future implementation follows explicit requests.
- Guide the owner through one unfinished Kanban card at a time. Do not provide implementation code unless requested.
- Use repository contents and the latest verified review to determine status. Distinguish implemented, verified, partially complete, blocked, and unstarted work. Mark a card Done only when its acceptance criteria have supporting evidence; compilation alone does not prove runtime behavior.
- Keep Java 25, stable Spring Boot 4.1.1, Boot-managed dependency versions, and the loose-coupling rules in the README.
- After an authorized review, update the `MILESTONES.md` tracker with actual evidence and unresolved issues.
- Follow `.agents/skills/milestone-review/SKILL.md` for milestone reviews and authorized Git delivery. Preserve unrelated user changes.
